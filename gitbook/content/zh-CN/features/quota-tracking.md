# 配额与用量

Kitsune Router 在本地记录用量，并显示受支持上游提供的配额/重置数据。用量估算、提供商额度和账单不是同一概念。

## 正确理解数据

- 按路由使用真实输入、输出及缓存计数；缺失值不虚构为零。
- 配额可能按账户、模型、服务或窗口划分。探测失败不等于重新获得额度或账户无效。
- **未知价格不等于免费。** 已知小计加未定价请求数不是完整总额。
- 实际速度档位可能不同于请求档位；订阅积分不是 API 美元账单。见 [速度](https://github.com/ByKitsune/kitsune-router/blob/master/docs/PROCESSING-SPEED.md)。
- 重试可能计费；客户端取消不证明上游已停止计费。token 上限不是完整金额预算。

## 仪表盘刷新

在 2026-10-29 的源码变更中，用量更新提交后会合并触发所选时段统计和图表的刷新；连接或重新连接时也会刷新。连接旧服务器时，累计总量或明细的变化可触发刷新，但全时段快照不会替换所选时段的数据。升级前已打开的标签页需要重新加载，才能使用新版客户端。

刷新失败时，仪表盘保留上次成功的数据，并标明数据实际对应的时段；可使用重试按钮，若会话过期则重新登录。仅仅经过一段时间不会触发刷新：请切换时段或重新加载页面。如果被比较的所有累计总量和明细均未变化，旧版数据流也无法发现变化。生产环境中原先仪表盘问题的根因尚未确认。

## 价格覆盖范围

models.dev 参考值保留精确的提供商产品和模型 ID。只有兼容的公开按量付费文本 token 费率可用于目录估算；订阅、媒体单位、条件费率或询价产品不会自动成为 token 价格。调度器每六小时尝试获取并验证完整目录。每次观测仅从实际观测时刻起适用，有效时间不足24小时，并按请求的记录时间选择。获取失败或 HTTP 304 不会延长有效期；`MODEL_CATALOG_SYNC=off` 关闭网络刷新，但保留已保存观测的读取。历史费用不会重新定价，缺失的费用组件仍为未知，参考值不是账单。参见[当前完整注册表审查](https://github.com/ByKitsune/kitsune-router/blob/master/docs/audit/22-pricing-capability-localization-2026-10.md)。

用量账本目前不保存 OpenCode 返回的 `usage.cost` 和 Go 额度字段。请在提供商的仪表盘查看这些数值；额度不等于现金收费。

## 存储与监控

配置和活跃用量共享 `${DATA_DIR}/db/data.sqlite`。`usage.json`/`db.json` 仅是历史迁移输入。使用绝对路径，停止后备份整个目录，包括密钥、身份与证书。见 [运维](https://github.com/ByKitsune/kitsune-router/blob/master/docs/OPERATIONS.md)。

先检查当前需认证的 `/api/metrics` 输出再写告警，勿对滚动窗口快照盲用 `rate()`/`increase()`。`/api/health` 不验证实时上游权限，历史测试数量也不证明当前版本。压缩没有固定节省比例，真实费用以上游账单为准。
