# API-Key Providers and Cost Choices

The historical “cheap” category is a documentation grouping, not a routing priority or price guarantee. Choose supported providers or a compatible endpoint based on your workload, required capabilities and current contract.

## Add an API connection

1. Obtain a provider key through that provider's official flow and confirm its terms/region.
2. Add the supported provider or compatible node in the dashboard, using its documented endpoint and model namespace.
3. Review the actual model catalog and capability limits. Public API, reseller and coding-plan IDs/prices are not interchangeable.
4. Create a gateway key for clients and optionally add the route to a combo in your preferred order.

Never paste provider secrets into a public issue or commit them to config examples. Use an absolute private `DATA_DIR` and keep full backups. A key stored locally is not necessarily encrypted at rest.

## Compare costs honestly

Prices depend on model, endpoint, date, context length, cache lifetime, media units and delivered service tier. Stale “$0.20/1M” tables cannot establish today's invoice. Use current provider billing and the dashboard's reviewed metadata/overrides; unknown prices remain unknown, not zero.

Compression savings vary. Fallback can consume additional paid attempts. No fixed savings percentage or never-exceed-budget promise is made.
